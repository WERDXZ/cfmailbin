# 日常收验证码

## 每次怎么用

1. 首次完成域名收件接入后，注册网站时直接填写一个普通地址，例如
   `github@example.com`。无需先在 cfmailbin 新建邮箱，也不需要 `+` 标签。
2. 打开 cfmailbin，收到的邮件按时间倒序排列。验证码直接显示在列表右侧，点击即可
   复制；核对同一行的发件人、收件地址和时间。未识别到代码时，点击邮件展开正文。
3. 页面可见时通过 SSE 实时更新，断线自动重连，连接失败时每 30 秒检查一次。
   切回标签页或窗口立即检查，隐藏时暂停。新邮件会
   出现在最前面，不会自动切换已经展开的正文，也不会自动覆盖剪贴板。
4. 用过的地址自动保留在侧栏。顶部搜索同时用于找邮件和旧地址，支持网站备注、
   地址、发件人、主题和正文摘要。点击地址旁的「复制」即可再次使用。
5. 将注册地址和账号一起保存在密码管理器中。以后登录、找回账号仍使用原来的地址。
   选中侧栏地址可以只看这个地址的邮件，无需进入额外的等待模式。

列表最多显示最近 100 封匹配邮件，搜索可以找到更早的邮件。邮件中的链接需要
展开正文后手动打开；不会自动访问。浏览器拒绝剪贴板访问时会提供可选中的文本。

## 首次接入

第一次部署完整项目请按 [部署步骤](deploy.md) 先建立存储、Worker 和登录保护，
再接入以下邮件路由。

1. 在 Cloudflare Email Routing 中启用自己的域名并完成邮件 DNS 配置。
2. 将该域名的 catch-all 路由指向 cfmailbin Worker。已有 catch-all
   时先确认其用途。 cfmailbin 不会自动创建或读取 Cloudflare 路由规则，也不会修改
   DNS。
3. 在 `wrangler.toml` 的 `[vars]` 中设置：

   ```toml
   CFMAILBIN_EMAIL_DOMAIN = "example.com"
   CFMAILBIN_ALLOW_CATCH_ALL = "true"
   CFMAILBIN_DEFAULT_RETENTION_DAYS = "7"
   ```

   Cloudflare catch-all 负责将邮件送到 Worker；应用的 `ALLOW_CATCH_ALL` 负责记住
   新地址并接收其邮件。两层都需要配置。填写域名本身不会建立路由。
4. 配置实际 D1、R2 资源和 [Cloudflare Access](access.md)。部署新代码前，用
   Wrangler 对目标 D1 应用 `src/db/migrations` 中的全部未应用迁移，包括
   `0003_inbox.sql` 至 `0006_alias_tags_repair.sql`。
   新迁移保留现有地址、邮件与规则，补充验证码摘要、最后收件时间、规则执行记录和
   AI 识别结果。即使不启用 AI，也需要执行全部迁移；0006
   修复早期数据库缺少地址标签表的问题。
5. 从其他邮箱向该域名下的新地址发送测试邮件。在「设置 → 收件接入」检查真实
   收件记录，并确认新地址出现在侧栏。首次收到前，状态是「尚未验证收件」。

仓库的部署配置开启未知地址收件。显式设为 `false` 时，需在「设置 →
手动登记地址」预先登记地址，未知地址将被拒收。本地服务的未配置默认值仍为
`false`。

## 保留与设置

设置有独立地址 `/settings`，分为收件、验证码识别、规则和账号。 收件偏好、AI
开关、模型和每日额度可以直接保存，无需改代码或重新部署。 生产设置保存在
KV；不同节点可能需要约一分钟或更久生效。邮件、规则和准确的 每日调用计数仍保存在
D1。密钥和登录身份继续由 Cloudflare 部署配置管理。
默认值来自环境变量，首次保存后以设置页为准。本地开发的设置随服务重启清空。

**地址长期保留，邮件短期保留。** 默认邮件保留 7 天，后台每小时清理到期邮件及
原件；删除或清理邮件不会删除地址及最后收件时间。选中地址后的「邮箱设置」可以
填写网站/用途备注、调整新邮件保留天数或停用收件。调整期限不追溯修改旧邮件。

停用地址也会拒收登录和找回账号的邮件，需要时先恢复。高级规则和手动登记地址
集中在设置中；邮件标签、状态修改、删除和 `.eml` 下载位于展开的正文中。

## 收件规则和模板

在「设置 → 收件规则」选择模板，点击「使用模板」填入草稿。模板不会自动安装。
检查条件和动作后，可先「用最近邮件试运行」，再保存启用或保存为停用。

| 模板         | 默认行为                                             |
| ------------ | ---------------------------------------------------- |
| 验证码       | 添加验证码标签，保留 1 天，继续后续规则              |
| 激活与找回   | 按主题匹配，保留 30 天并停止后续规则                 |
| 营销邮件     | 移入垃圾箱，排除已识别验证码及常见账号、安全提醒主题 |
| 按网站分类   | 按地址通配符添加标签，继续后续规则                   |
| 账号安全提醒 | 转发并保留，使用前填写目标邮箱                       |

- 条件支持「全部满足」「任一满足」和「排除」，复杂组可折叠。文字匹配忽略大小写；
  通配符 `*` 表示任意长度，`?` 表示一个字符，匹配整个字段。
- 发件地址和域名使用信封发件地址，和收件箱列表一致；它不是发件人身份认证。
- 可以同时设置处理方式、标签和保留天数。规则从上往下执行，箭头调整顺序；标签
  累加，后面命中的处理方式和保留天数覆盖前面的值。「执行后停止」阻止继续匹配，
  拒收始终停止。转发在最终决定后才执行。
- 标签分类通常放在前面并继续执行；保护账号邮件的规则适合放在营销规则前面。
- 试运行只检查最近 20 封适用地址的邮件，按当前顺序模拟启用该草稿。编辑已有规则
  会替换原位置，新草稿追加到末尾。结果会说明匹配条件和提前停止，不实际转发、
  拒收或修改历史邮件。
- 正文无法完整读取时，不能确定的条件显示「无法判断」，不会因 NOT 而误命中。
- 新邮件展开正文后的「收件时的规则记录」显示当时命中的规则和原因，之后编辑
  规则不会改写历史。被拒收的邮件不存正文，原因保存在拒收审计记录中。

规则仅影响新收件。模板与验证码识别都有局限，建议先试运行检查匹配结果。

## 没收到邮件时

- 「连接后端失败」表示浏览器未能读取最新结果，自动重试恢复前显示的可能是旧数据。
- 「尚未验证收件」表示没有该配置域名的成功收件记录，不表示已经完成路由接入。
- 「最近收件」来自应用收到邮件后的持久记录，不读取 Cloudflare 配置，也不能保证
  此后的每封邮件都能送达。删除邮件不抹掉这条接入证据。
- 设置中显示最近的拒收记录，可区分未知地址、停用地址和规则拦截。
- 检查网站填入的地址、域名 DNS、Email Routing 的 Worker 目标、地址是否启用、
  应用是否允许未知地址，以及全局/地址规则。默认显示全部邮件状态，避免漏看垃圾箱。
- 有些网站会限制整个自定义域名；没有 `+` 标签也不保证所有网站都接受。

## 验证码与正文

可选 AI 补充识别通过 Cloudflare AI Gateway（BYOK）调用 DeepSeek V4.1 Flash 或
GPT-5.6 Luna。开启后，本地未找到
验证码的邮件会在入库后后台分析，结果显示在原来的复制按钮和分类提示中。每封
记录最多调用一次，默认每天最多 100 次；失败时仍可查看正文。设置页显示配置状态。
详见 [价格与启用方式](email-analysis.md)。当前收件规则和试运行仍使用本地识别，
不会因后来的 AI 结果重新转发或拒收。

验证码识别依赖上下文，支持常见中英文提示、4–8 位数字、混合字母数字和分组的
六位数字，最多显示三个候选。保留开头的零和字母大小写。**显示代码不代表仍有效**，
以发送网站的时限和最新邮件为准。

新邮件入库时提取验证码。旧邮件列表先从已保存的主题和摘要中识别，打开正文时
补充完整提取结果；列表刷新不读取原始
MIME。支持纯文本、HTML、Base64、Quoted-Printable
等常见格式，默认显示纯文本，也可切换到隔离的 HTML
预览；不加载远程图片或执行脚本。附件保留在 `.eml` 中。

超过 1 MiB 的原件不在网页解析，格式异常也会提示下载原件。正文最多显示 50,000
字符。原件仍受邮件保留期限约束。

## 本地开发

分别运行 `deno task dev` 和 `deno task ui:dev`，打开 `http://127.0.0.1:5173`。
本地服务使用内存，重启会清空数据，不接收 Cloudflare 邮件。真实域名收件和 Access
登录需要在配置好的部署环境中验证。
